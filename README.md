# goit-de-hw-03

Домашнє завдання №3: аналіз покупок через PySpark DataFrame API.

## Файли

- `main.py` — усі шість етапів завдання з українськими коментарями.
- `data/` — три оригінальні CSV із завдання.
- `results/` — фактичний текст `df.show()`, підсумкові CSV та результат перевірки.
- `screenshots/` — пронумеровані PNG виводу `df.show()` для кожного етапу.
- `requirements.txt` — версія PySpark, на якій перевірено код.

## Запуск

Потрібні Python 3.10–3.12 та Java 17. Перевірено на Python 3.12, Java 17,
PySpark 3.5.3. Якщо Java не знайдено, налаштуйте `JAVA_HOME` та `PATH`.

```bash
python -m venv .venv
```

Активація у Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Активація у macOS/Linux:

```bash
source .venv/bin/activate
```

Встановлення й запуск із каталогу проєкту:

```bash
python -m pip install -r requirements.txt
python main.py
```

Програма виводить результати в консоль і записує їх у `results/`.
За проблем із визначенням локальної адреси Spark задайте
`SPARK_LOCAL_IP=127.0.0.1` (PowerShell: `$env:SPARK_LOCAL_IP="127.0.0.1"`).

## Джерела

В умові переплутані посилання на покупки та товари. Файли збережено за їхніми
фактичними назвами й заголовками колонок:

- [users.csv](https://drive.google.com/file/d/1GN8o8vYP8LLj3A0UWkvbgnf0YjcF3PkV/view)
- [purchases.csv](https://drive.google.com/file/d/1cDLTc0KYQfnsDWHLR0cJkF5puBpAo2Uh/view)
- [products.csv](https://drive.google.com/file/d/1im5cGVl1z8ejypTyNJZSQ2lqMGh6tTFN/view)

## Етапи

1. CSV читаються в три окремі DataFrame з явними типами колонок.
2. `dropna(how="any")` видаляє рядки з пропусками в будь-якій колонці кожного DF.
3. Покупки з'єднуються з товарами за `product_id`. Вартість рядка дорівнює
   `quantity * price`. Суми групуються за категорією.
4. Додаються очищені користувачі за `user_id`, застосовується `age.between(18, 25)`.
5. Відсоток дорівнює `сума категорії для 18–25 / загальна сума для 18–25 * 100`.
   Округлення — до двох знаків після коми. За нульового знаменника частка — `NULL`.
6. Обираються три найбільші частки. Для спільного додатного знаменника сортування
   за сумою тотожне сортуванню за точною часткою та не втрачає точності через
   округлення. За однакових сум використовується назва категорії.

Для етапу 3 таблиця користувачів не потрібна: пропущений email або вік не повинен
виключати покупку з загальних витрат. Для етапів 4–6 використовуються лише
повністю заповнені рядки користувачів. `inner join` виключає покупки, для яких
немає відповідного запису в потрібній очищеній таблиці. Валюта в умові не задана.

## Скриншоти

Назви починаються з `p1_`–`p6_`. Етапи 1 і 2 містять окремі зображення для
кожного DataFrame; етап 2 також містить зведення очищення.
Для вихідних таблиць показано перші 20 рядків, як у стандартному `df.show()`;
агрегації показано повністю. Текстові оригінали містяться в `results/`.
PNG отримано захопленням вікна текстового переглядача Qt, який показує
незмінений збережений вивід реального запуску `df.show()`.
